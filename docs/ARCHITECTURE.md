# Архитектура проекта

## Общие принципы

### REST API
Проект построен на принципах REST API с использованием Django REST Framework:
- Все endpoints следуют RESTful соглашениям
- Использование HTTP методов (GET, POST, PUT, PATCH, DELETE)
- Стандартные HTTP статус коды
- JSON формат данных

### SOLID принципы

1. **Single Responsibility Principle (SRP)**
   - Каждый модуль отвечает за свою область:
     - `core` - базовые функции и общие утилиты
     - `news` - управление новостями
     - `torrents` - работа с торрентами
     - `notifications` - система уведомлений
   - Бизнес-логика вынесена в отдельные сервисы (`services.py`)

2. **Open/Closed Principle (OCP)**
   - Код открыт для расширения через наследование и композицию
   - Закрыт для модификации - изменения в базовых классах не требуются

3. **Liskov Substitution Principle (LSP)**
   - Производные классы могут заменять базовые без нарушения функциональности
   - Правильное использование абстрактных базовых классов

4. **Interface Segregation Principle (ISP)**
   - Разделение интерфейсов на более мелкие и специфичные
   - Каждый класс использует только нужные ему методы

5. **Dependency Inversion Principle (DIP)**
   - Зависимость от абстракций (интерфейсов), а не от конкретных реализаций
   - Использование dependency injection через сервисы

## Структура модулей

Каждый модуль (`app`) имеет следующую структуру:

```
app_name/
├── __init__.py
├── apps.py              # Конфигурация приложения
├── models.py            # Модели данных (MVC Model)
├── serializers.py       # Сериализаторы для REST API
├── views.py             # Представления (MVC View)
├── urls.py              # URL маршруты
├── admin.py             # Административная панель
├── services.py          # Бизнес-логика (SOLID)
├── permissions.py       # Разрешения доступа
├── tasks.py             # Celery задачи (если нужны)
└── tests.py             # Тесты
```

## Разделение ответственности

### Models (`models.py`)
- Определение структуры данных
- Валидация на уровне модели
- Связи между моделями
- **НЕ содержит бизнес-логику**

### Serializers (`serializers.py`)
- Преобразование данных модели в JSON и обратно
- Валидация входных данных
- Настройка полей для API

### Views (`views.py`)
- Обработка HTTP запросов
- Вызов сервисов для бизнес-логики
- Возврат HTTP ответов
- **Минимальная логика, только координация**

### Services (`services.py`)
- Вся бизнес-логика
- Комплексные операции
- Следование SOLID принципам
- Переиспользуемый код

### Permissions (`permissions.py`)
- Проверка прав доступа
- Кастомные классы разрешений

## Пример работы запроса

```
HTTP Request
    ↓
URL Router (urls.py)
    ↓
View (views.py)
    ↓
Serializer (serializers.py) - валидация
    ↓
Service (services.py) - бизнес-логика
    ↓
Model (models.py) - работа с БД
    ↓
Response (через Serializer)
```

## Модули проекта

### Core (`apps/core/`)
**Ответственность**: Базовые функции, общие утилиты
- Health check endpoints
- Общие модели (если нужны)
- Общие permission классы
- Базовые сервисы

### News (`apps/news/`)
**Ответственность**: Управление новостями по играм
- CRUD операции для новостей
- Категории новостей
- Комментарии
- Поиск и фильтрация

### Torrents (`apps/torrents/`)
**Ответственность**: Работа с торрент-файлами
- Загрузка торрент-файлов
- Управление загрузками
- Интеграция с libtorrent
- Статистика загрузок

### Notifications (`apps/notifications/`)
**Ответственность**: Система уведомлений
- Email уведомления (через Celery)
- Настройки подписок
- История уведомлений
- Шаблоны уведомлений

## Дополнительные компоненты

### Celery
- Асинхронная обработка задач
- Отправка email уведомлений
- Обработка торрент-загрузок

### Redis
- Брокер сообщений для Celery
- Кеширование (опционально)

## Рекомендации по разработке

1. **Всегда используйте сервисы для бизнес-логики**
   - Не размещайте логику в views или models

2. **Следуйте RESTful принципам**
   - Используйте правильные HTTP методы
   - Правильные статус коды

3. **Пишите тесты**
   - Unit тесты для сервисов
   - API тесты для endpoints

4. **Документируйте код**
   - Docstrings для функций и классов
   - Комментарии для сложной логики

5. **Соблюдайте PEP 8**
   - Форматирование кода
   - Именование переменных и функций
